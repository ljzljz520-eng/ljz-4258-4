# 运行与职责模型

## 1. 主数据与批段

批段声明阀组、取样管线、产品批、目标压力阶段标签、基线窗口和稳定窗口。样品必须引用该批段、实际测点和粒度算法版本。

## 2. 导入

操作员上传多文件后仅创建 `PENDING` 作业。Worker：

1. 用作业行锁和租约领取任务；
2. 每个文件在 `REQUIRES_NEW` 事务中独立落库；
3. 成功保留 checksum 与样品引用，失败记录错误并回滚该文件；
4. 汇总状态；只有全部成功才是 `SUCCEEDED`；
5. 失败文件可修正后由同一作业重试。

## 3. 自动配对

自动扫描只做确定性提议：同段、同层、前样实际取样时间早于后样；对每个后样取最近前样。一个前样可被多个后样阶段引用，因此是一对多候选。自动扫描不会确认或审核。

## 4. 人工边界

实验员可改选候选、刷新 STALE、确认当前无 blocker 的候选；所有人工选择仍由服务端重新执行全部规则。审核员只锁证和签发，不参与配对、导入或修正。

## 5. 压力修正

压力修正不是 UPDATE 原始证据，而是：

- 新增版本化 `pressure_calibration_mappings`；
- 旧版本失活；
- 读取产生新的 corrected bar；
- 依赖旧映射的比较标 STALE 并显示 `PRESSURE_MAPPING_CHANGED`；
- 刷新依赖并重新确认后才能进入证据快照。

## 6. 锁证与签发

锁证前检查：最新导入完整成功、每个后样都有已确认候选、已确认候选没有 blocker。锁证生成不可变 JSONB 与 SHA-256。签发时重新计算当前证据指纹，任何导入、修正或候选变更造成的差异都会阻止签发。

## 7. 明确非目标

- 不计算“推荐压力”；
- 不向均质机、PLC、SCADA 或 OPC 服务写入设定值；
- 不允许前端绕过服务端角色与规则；
- 不把部分成功导入呈现为完整成功。
